# Use one patched local SQLite database

The Portal will keep delivery state, exact Raw Records, canonical and derived state, deletion state, and durable processing jobs in one SQLite database on the home server's local filesystem. Production will require a patched SQLite runtime, preferably `3.51.3` or newer, use WAL with `synchronous=FULL`, keep transactions short, and start with one Portal process and one processing worker; PostgreSQL remains a response to measured lock contention or a real multi-writer requirement. The application will not add SQLCipher or field-level database encryption; deployment-provided full-disk protection and encrypted backup destinations own data-at-rest security. This accepts a single-writer and deployment-security boundary in exchange for atomic ingestion and a minimal single-Operator deployment while avoiding the WAL-reset corruption range that includes the repository's current SQLite `3.50.4`.
