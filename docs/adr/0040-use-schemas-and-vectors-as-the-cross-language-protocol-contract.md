# Use schemas and vectors as the cross-language protocol contract

Each language that encodes or decodes Sender ingress messages—TypeScript on the Sender and Python on the Portal—will share versioned JSON Schemas plus canonical positive and negative byte vectors from the repository's `protocol/` tree. Each keeps explicit encoders and decoders, and its tests must consume the same vectors for exact bytes, hashes, rejection outcomes, and version compatibility. Kotlin hands opaque Source Projection bytes to the TypeScript shell (ADR 0010), so it joins these vectors only if it later takes on wire encoding or decoding; its projection bytes are governed by `project-source-record`. Portable Export has a distinct shared contract, schema inventory, documentation, validator behavior, and synthetic conformance fixtures because its external-reader compatibility and package semantics differ from wire delivery, even when individual field schemas can reuse governed definitions. This avoids generated models becoming an accidental least-common-denominator interface or conflating two version lifecycles, at the cost of maintaining deliberate mappings and fixtures.
