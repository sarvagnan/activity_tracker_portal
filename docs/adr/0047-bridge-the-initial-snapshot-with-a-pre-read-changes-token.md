# Bridge the Initial Snapshot with a pre-read changes token

Before reading the first page of each record type's Initial Snapshot, the Sender will obtain a separate Health Connect changes token and durably commit it with a new snapshot identity and empty chain state. Snapshot progress, page and record counts, cumulative digest, next page position, token, and cursor state then commit atomically with every staged message so an interruption resumes the same identity without regenerating queued bytes. After Snapshot Completion is acknowledged, the Sender drains a catch-up Change Cycle from the pre-read token, and first summary publication waits for its accepted Change Completion and terminal processing. If that token expires before first publication, the incomplete attempt and all of its evidence remain retained but abandoned, none of it publishes, and a new token and Initial Snapshot identity begin a full new attempt. This may replay records that the snapshot already observed and delays first values, but Source Identity reconciliation makes repetition safe and the bridge prevents concurrent insert, update, or deletion from falling between baseline and ongoing synchronization.
