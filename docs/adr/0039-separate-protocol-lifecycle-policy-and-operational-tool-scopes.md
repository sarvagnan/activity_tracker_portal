# Separate protocol, lifecycle, policy, and operational-tool scopes

Executable wire behavior belongs to the shared `ingest-protocol` scope, while Sender Installation lifecycle is governed independently from delivery. Amendments, Source Selection Policy changes, and Fallback Timezone Policy changes remain separate leaf scopes because their intent and acceptance oracles differ. Portable export composition and compatibility belong to the shared pure `portable-export-contract` scope, while effectful snapshot capture and publication belong to `produce-portable-export`; backup creation, restoration, migration, and health-data-free diagnostics each remain separate integration scopes, and backup and restore stay separate because restoration carries far greater authority. Batch acceptance requires Authorized Ingress, but version one does not create a generic authentication scope or adapter for its sole Tailscale-based mechanism. This creates more lifecycle carriers in exchange for local failure semantics, explicit authority, and avoiding both operational god-modules and hypothetical seams.
