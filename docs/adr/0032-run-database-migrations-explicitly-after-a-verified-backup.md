# Run database migrations explicitly after a verified backup

Portal startup performs a read-only schema compatibility check and refuses service when migration is required; it does not mutate the operational database automatically. An explicit `portal migrate` operation stops or excludes competing Portal processes, acquires the database exclusively, creates and verifies a pre-migration Operational Backup, and applies ordered checksummed migrations transactionally. Schema downgrades are not promised: a code rollback must declare compatibility with the already-applied schema, otherwise recovery uses a compatible release or the verified backup plus the latest Deletion Ledger. This adds an operator step during upgrades in exchange for a visible recovery point and freedom from partially automatic migration failures.
