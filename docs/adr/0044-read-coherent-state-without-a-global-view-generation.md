# Read coherent state without a global view generation

Processor Generation, active policy identities, Canonical Revisions, and Health Summary revisions will remain distinct selectors rather than being wrapped in a global generation that changes on every receipt. The Operational Store will expose one deep current-state read interface backed by a single SQLite read transaction. Processor Generation activation, policy activation, and first atomic publication after an Initial Snapshot update all affected selectors atomically and append a health-data-free Cutover Record; ordinary processing and summary refresh do not. Deletion uses its Deletion Receipt, while backup, restore, and migration retain their own operational evidence. This relies deliberately on SQLite snapshot and transaction guarantees in exchange for simpler ordinary ingestion, coherent browser and export reads, and an inspectable account of exceptional multi-result cutovers without another pervasive lifecycle concept.
