# Encrypt and exclude the Sender outbox from backup

Enrollment requires a secure Device screen lock. Each Outbox Message will be encrypted independently with AES-256-GCM using a non-exportable installation key held by Android Keystore, then stored as a BLOB in the Sender's credential-encrypted `expo-sqlite` database so its outbox row, sequence, and applicable per-type cursor or snapshot state can commit atomically. Health-data-free bookkeeping may remain plaintext inside that private database. All Sender state is excluded from cloud backup and device migration; a restore is a new Sender Installation that must enroll and reconcile rather than resurrect an identity or outbox. Removing the secure lock stops new collection while allowing the existing outbox to drain; an unusable key freezes the installation for explicit Operator retirement, and storage pressure stops polling before existing ciphertext is endangered. This accepts deliberate migration friction, visible blocked states, and unrecoverable queued data after key or Device loss in exchange for never silently discarding data and limiting backup leakage and copied-filesystem exposure.
