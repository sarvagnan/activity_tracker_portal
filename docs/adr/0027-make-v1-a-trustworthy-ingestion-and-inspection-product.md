# Make v1 a trustworthy ingestion and inspection product

The first useful Portal release is complete when it can enroll the Sender, archive every permitted Health Connect type, expose sync and processing state, show retained records in a generic chronological inspector with provenance, process Steps, Heart Rate, Sleep Session, and Weight into basic trends, and perform export and deletion. Exercise Session follows after representative Device evidence is captured; Nutrition and other safely archived types remain Unmodeled until real source evidence supports their interpretation. The record inspector defaults to the latest seven days, uses stable cursor pagination and time, type, origin, and state filters, and lists a dense series as one Source Record whose detail exposes the complete projection, every observing Sender Installation, revisions, and Amendments. Durably archived records and completed revisions remain inspectable during an incomplete Initial or Reconciliation Snapshot, clearly tagged with that snapshot identity and state. Abandoned Attempt Evidence remains available under an explicit filter and conspicuous condition but is never presented as current or contributing evidence; it can contribute only if independently reacquired through a completed attempt. Overview health values and derived summaries stay withheld before initial snapshot and catch-up completion, while an established result stays visible with reconciliation-pending during a later full reread. Advanced cross-metric comparison and comprehensive type-specific presentation are deferred. This gives the Operator a trustworthy, inspectable data route early without requiring another Sender release when additional processors are introduced.
