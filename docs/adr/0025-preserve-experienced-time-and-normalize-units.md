# Preserve experienced time and normalize units explicitly

Canonical processing will preserve every source UTC instant, each independently nullable experienced zone offset, and whether a planned activity has an explicit time. Calendar derivations use the experienced offset when present. When it is absent, they use an append-only, effective-dated Fallback Timezone Policy, mark the attribution as inferred, and bind the result to a processor version rather than inheriting the Portal server's timezone. Setup may propose an IANA timezone from the browser but the Operator must confirm it; the initial policy covers all retained history without an explicit offset. Later changes default to the change instant but may be backdated deliberately. Missing policy never blocks archival: affected Raw Records become Policy-Pending rather than Quarantined or Unmodeled. Changing policy creates new Canonical Revisions wherever inferred temporal headers change and then rebuilds dependent summaries, while explicit source offsets remain authoritative. Date-only plans remain date semantics and are not converted into real noon observations. Each typed property has one documented canonical storage unit, conversions do not deliberately round, integer and floating representations remain distinct, and v1 renders documented metric units while Portable Exports retain canonical units. Configurable display units are deferred. This gives reproducible time and unit semantics while preserving uncertainty that the source did not resolve.
