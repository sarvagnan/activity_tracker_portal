# Separate observation, delivery, processing, storage, and presentation scopes

The Governed Scope graph uses stable behavioral capabilities rather than phases, files, tables, or framework layers. One shared, pure `project-source-record` module defines exact typed-record projection bytes, while `read-snapshot-page` and `read-change-page` remain separate leaves because they have different cursors, failures, retractions, outputs, and acceptance oracles. Both readers stay separate from durable outbox staging so a tentative cursor advances only with encrypted local durability; Sender transmission and Portal acceptance are joined by receipt-bound integration evidence. Expo BackgroundTask is a scheduling adapter whose callback shares the durable `coordinate-sender-sync` interface with foreground and manual trigger adapters; scheduling owns no cursor or outbox semantics. `complete-initial-snapshot` crosses observation, delivery, processing, and first publication so an arbitrary first baseline page cannot masquerade as complete history. `complete-replacement-baseline` separately preserves established results and refuses cross-installation absence inference, while `complete-reconciliation-snapshot` requires its full reread and catch-up completion before atomically activating qualified evidence. Source reconciliation is a deterministic leaf independent from the shared interpretation contract. Steps, Heart Rate, Sleep Session, and Weight each own concrete interpretation and summary leaves because their inputs, outputs, and acceptance oracles differ, while common revision, summary-state, range-composition, and reversible duplicate-grouping vocabulary remains shared. Pure summary calculations remain separate from `refresh-summary-state`, whose durable work coordination and conditional publication use one deep Operational Store. Processor Generation activation atomically includes affected summary revisions and prevents mixed-version ordinary views. The shared pure `portable-export-contract` module owns versioned package composition and conformance, while `produce-portable-export` alone owns snapshot capture, durable job state, and artifact publication. Privacy deletion remains its own integration scope, while rendering consumes shared summary states and preserves their distinctions through the UI. This creates more governed scopes and dependency edges in exchange for concrete functional contracts, durable retries, and coherent version cutovers.
