# Receive Android data through direct push

The project will own a purpose-built Android Sender as a first-class participant. It will push health-data deliveries directly to a narrow Portal HTTP ingress reachable over Tailscale. Version one treats Authorized Ingress as a precondition of batch acceptance: narrow transport code establishes that precondition and maps the shared Wire Protocol into transport-independent ingestion behavior, without inventing a generic authentication seam while only one mechanism exists. A future application-level mechanism can establish the same precondition without changing ingestion semantics. The Portal will preserve the exact received payload before issuing a Delivery Receipt, make repeated deliveries safe, and retain enough delivery metadata to investigate gaps. The authoritative delivery contract must account for stable identity, corrections, deletions, retries, and acknowledgements. An incompatible off-the-shelf Sender will not be used merely as a preliminary integration. This accepts ownership of Android delivery code in exchange for trustworthy, project-specific ingestion.
