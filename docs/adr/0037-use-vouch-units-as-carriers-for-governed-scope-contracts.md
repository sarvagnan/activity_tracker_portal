# Use Vouch units as carriers for Governed Scope contracts

Until Vouch implements first-class scopes, each project Vouch unit will act as the versioned lifecycle carrier for one project-owned Governed Scope contract. A leaf scope owns cohesive product behavior and its primary paths, a shared scope owns common behavior consumed through contracts, and an integration scope owns behavior crossing scopes or an effect seam. Every contract declares purpose, concrete inputs, outputs, named failures, observable effects, authority, dependencies, and acceptance oracle. Pure, effectful, or volatile inputs influence dependency contracts and verification reuse but do not determine ownership. Each relevant path has one primary scope; cross-scope acceptance belongs to an explicit integration scope rather than an oversized feature unit. A project test mechanically validates contract shape, and the contract and test are byte-bound into the acceptance pack, while the Operator remains responsible for semantic adequacy because current mk2 does not understand these fields. This restores legible functional boundaries and follows Vouch's accepted target architecture without claiming that current lifecycle mechanics enforce it.
