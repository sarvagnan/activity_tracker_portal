# Observe Health Connect without becoming a producer

The Sender will request only explicitly approved Health Connect record types, read every origin within those types, and never write, edit, or delete Health Connect data. Before the first page of a resumable per-type Initial Snapshot, it durably stores a separate changes token so a later catch-up Change Cycle captures inserts, updates, and deletions that race with the baseline traversal. Snapshot and change-cycle pages may archive and process incrementally, but the first ordinary health value cannot publish until both completion messages are accepted and every page reaches a terminal outcome; later change cycles likewise publish affected summaries only after their completion and terminal processing. Progress remains health-data-free until first publication. Matching Source Identities reconcile across observing Sender Installations, but merely similar records from distinct identities or origins remain separate and derived calculations must use an explicit Source Selection Policy. Source modification time, not Portal arrival order, selects newer evidence. Older arrivals remain retained without displacing current evidence; different bytes at the same source modification time create an explicit Source Conflict and leave the prior current state unchanged rather than choosing arbitrarily. Both conflicting projections remain inspectable and the conflict stays visible until source evidence with a later modification time establishes a new order. The Operator may exclude or explicitly delete a Source Record, but cannot choose which equal-time projection becomes source truth, and an Amendment cannot rewrite source ordering. Affected summaries may continue showing their last trusted value, but must carry a visible conflict condition, exclude both unordered projections, and link to the conflicting evidence rather than presenting that value as clean current evidence. Permission loss pauses only the affected type without advancing its saved position or implying that prior records were deleted. After regrant, the Sender first attempts that exact position; a successful source response resumes continuity, while an invalid or expired position abandons the incomplete attempt and begins a new Initial Snapshot before baseline or Reconciliation Snapshot afterward. No completion is issued while permission is absent. Disabling collection is a reversible pause: no new source read starts, an already active source call may finish only through atomic durable staging, no false completion is issued, the exact token, cursor, and attempt identity remain saved, queued Outbox Messages drain, and retained Portal data remains. Scheduled Polling Runs continue to prove contact without source reads, reporting affected types as deferred with reason collection-disabled. Re-enabling attempts the saved position before the existing invalid-continuity path applies; v1 has no separate snapshot-cancellation operation because collection control is not deletion. Source corrections create new Raw Records. Source deletions are archived as immutable Source Retractions linked to the Source Record; they deactivate the current Canonical Revision and rebuild affected summaries without erasing prior evidence, while a later newer projection may create and activate another revision. After a token loss, a prior identity absent from a completed Reconciliation Snapshot and catch-up cycle under the same Sender Installation and provably unchanged full-history, record-type, and origin coverage becomes a Reconciliation Absence that withdraws its contribution without claiming a source-issued deletion; uncertain coverage blocks reconciliation activation. Operator changes remain separate Amendments, and later source changes that conflict with one are surfaced. Accepted health evidence is never age- or pressure-pruned: low capacity stops ingestion until the Operator provides space or explicitly deletes data. This preserves provenance and keeps upstream applications authoritative, at the cost of handling duplicate origins and maintaining separate collection, amendment, and explicit-deletion workflows.
