# Evolve the wire protocol without coordinated upgrades

Every Outbox Message identifies its Wire Protocol Version; a data-bearing Ingest Batch additionally identifies the independent Source Projection schema version for its one record type. The Portal advertises supported versions and limits under a monotonically increasing capability generation, and the Sender durably caches that generation so it may continue staging while offline and acknowledges it with an ordered, receipt-bound Outbox Message. Every Outbox Message records the generation it was staged under, and the Portal evaluates its versions and limits against that generation. Because delivery is strictly ordered, accepting the acknowledgement of a later generation proves that every message staged under an earlier one has arrived; only then may the Portal stop honoring that earlier generation, whether it is retiring an old version or a higher limit. Limits include maximum record count and uncompressed byte size; the Sender uses them only when staging new messages, already queued bytes remain unchanged, and deterministically partitions a projected source page into numbered fragments committed with one cursor advance. One indivisible projection over the ceiling still blocks that type visibly instead of being split or dropped. Evolution follows expand–migrate–contract: upgrade the Portal to accept old and new formats, let the Sender adopt and acknowledge the new generation, drain old messages, and remove obsolete support only in a later governed release. This retains compatibility code and explicit capability state longer in exchange for offline collection safety and independent home-server and phone upgrades.
