# Govern forward delivery with Vouch at standard assurance

Every forward behavioral or architectural change will move through Vouch mk2 as a versioned unit at the `standard` assurance tier; exploration, glossary and decision-document edits, and housekeeping are exempt unless used to support a completion claim. Each unit acts as the current lifecycle carrier for one version of a project-owned Governed Scope contract rather than an arbitrary work ticket. Claude drafts each acceptance pack and records Vouch transitions; the Operator approves each draft's semantics; GPT 6 Astra, as a separate approver agent, approves the freeze binding, reviews implementation, approves pull-request merges, and accepts publication; and GPT 6.1 Sol, delegated through a T3 task, implements only after freeze. Each role is a separate agent, so the agent that drafts a pack never implements it and the implementer cannot edit the bound pack; material pack changes, contract conflicts, and plan gaps return to the Operator as deviations. Subject to a successful full test run from an isolated clean checkout, the first trust root will be built from exact Vouch commit `75f70a52353a773ab896b79a26396735e4e5a152`; its commit and lock digest will be recorded, and the resulting `vouch.lock` will be committed. On 2026-10-13 the trust root was re-pinned by the same procedure to exact commit `33201a5f4b7fa6ebd01a7e1a0b142fdac09f29e7`, which publishes Vouch's `merge-open-in-ci-replay@1`, with lock digest `0b9b4ef1d7cb3925e7677c0766ff2ba9f646d47b66b54fb4586f177a25e806d6`. On 2026-10-30 it was re-pinned to exact commit `48f1eb4d88b6a6145438ab00fa93c901cf44ce01`, which publishes Vouch's `anchor-unit-ref@1`, with lock digest `6bc9519bbca38405f7583b8b3fa0da0f36610d460a0b333b1fe474a6df40449b`. Each later re-pin follows the same procedure and records its commit and lock digest here. The live Vouch working tree is not an acceptable build source. This is an explicit alpha adoption probe until Vouch has a reproducible release, not a claim that Vouch is released. The project will commit the Vouch store and run its checks as a required GitHub status check. Beads remains the task and dependency tracker, while Vouch owns acceptance-pack binding, evidence, lifecycle, and publication gates. This accepts additional delivery ceremony and alpha-tool risk in exchange for mechanically pinned acceptance criteria, auditable evidence, and concrete first-adopter feedback.
