# Govern forward delivery with Vouch at standard assurance

Every forward behavioral or architectural change will move through Vouch mk2 as a versioned unit at the `standard` assurance tier; exploration, glossary and decision-document edits, and housekeeping are exempt unless used to support a completion claim. Each unit acts as the current lifecycle carrier for one version of a project-owned Governed Scope contract rather than an arbitrary work ticket. Claude drafts each acceptance pack, the Operator approves it before freeze, and Claude implements only after freeze; material pack changes, contract conflicts, and plan gaps return to the Operator as deviations. Subject to a successful full test run from an isolated clean checkout, the first trust root will be built from exact Vouch commit `75f70a52353a773ab896b79a26396735e4e5a152`; its commit and lock digest will be recorded, and the resulting `vouch.lock` will be committed. The live Vouch working tree is not an acceptable build source. This is an explicit alpha adoption probe until Vouch has a reproducible release, not a claim that Vouch is released. The project will commit the Vouch store and run its checks as a required GitHub status check. Beads remains the task and dependency tracker, while Vouch owns acceptance-pack binding, evidence, lifecycle, and publication gates. This accepts additional delivery ceremony and alpha-tool risk in exchange for mechanically pinned acceptance criteria, auditable evidence, and concrete first-adopter feedback.
