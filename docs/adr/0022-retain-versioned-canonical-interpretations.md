# Retain versioned canonical interpretations

Processing will create an immutable Canonical Revision under a named processor version and applicable policy identities rather than update a prior interpretation in place. Current views select revisions through one active Processor Generation: an immutable global manifest mapping every supported record type to its active processor version. A new generation reuses unchanged mappings and reprocesses only changed types, while earlier revisions and their processor and policy identities remain inspectable for as long as the corresponding Raw Record is retained. An upgrade or changed Fallback Timezone Policy builds candidate revisions for the complete affected set while the previous generation remains current. A candidate activates automatically only when every affected Processing Job and Summary Refresh Job completes and each Source Record's terminal outcome transition matches governed expectations; aggregate count equality alone is insufficient. Completed valid reclassifications may pause activation for health-data-free Operator approval, but new quarantine, Policy-Pending, Source Conflict, missing or invalid revision, failed invariant, job failure, or incomplete work cannot be overridden and leaves the prior generation current. Activation atomically selects the new processor manifest and every affected Health Summary so ordinary views never mix generations. A privacy deletion erases every canonical and derived revision in its scope along with the Raw Record. This costs additional storage and staged cutover state in exchange for reproducible history and coherent reprocessing.
