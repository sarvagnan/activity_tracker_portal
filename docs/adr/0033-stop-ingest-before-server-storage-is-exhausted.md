# Stop ingest before server storage is exhausted

The Portal first removes incomplete, expired, and then oldest completed server-side Portable Exports when approaching its configurable storage low-water mark. It does not prune retained health evidence. If that cannot restore the reserve, it stops admitting Outbox Messages, returns a retryable machine-readable storage outcome without a Delivery Receipt, and exposes a health-data-free operational alert. Capacity is reserved for the Deletion Ledger, live deletion, SQLite recovery, and bounded maintenance rather than allowing ingest to consume the final usable space. The Sender retains and retries its oldest Outbox Message and eventually stops new Health Connect collection under its local outbox-pressure policy. This can shorten the nominal seven-day export lifetime and pause collection while disk space remains in exchange for preserving deletion and recovery paths and preventing false durability acknowledgement.
